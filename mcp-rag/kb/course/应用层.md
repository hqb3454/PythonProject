# 计算机网络 · 应用层（课程讲义摘要）

## 应用层概述
- 应用层协议定义：应用进程交换的报文类型、语法与语义、发送与响应的时序规则。
- 两种体系结构：**客户-服务器 C/S**（服务器固定 IP、长期在线、被动接受请求）与 **P2P**（无中心服务器，节点既是客户又是服务器，可扩展性强）。
- 应用进程靠 socket API 与传输层交互，传输层选择 TCP（可靠）或 UDP（实时）。

## DNS 域名系统
- 作用：把域名解析为 IP 地址；基于 **UDP 53 端口**（区域传送时用 TCP）。
- 层次域名空间：根域 → 顶级域（.com / .cn / .edu / 国家域）→ 二级域 → 三级域…… 完整的域名称为 FQDN。
- 四类域名服务器：根域名服务器（13 组，任播）→ 顶级域名服务器 → 权限（授权）域名服务器 → 本地域名服务器。
- 查询方式：
  - **递归查询**：本地服务器代替主机查到底并返回最终结果（主机→本地服务器常用）；
  - **迭代查询**：服务器每次返回"下一步问谁"，由请求者自己继续查（本地服务器→各级服务器常用）。
- DNS 缓存：各级都有高速缓存并设 TTL，大幅减少根服务器压力。

## 文件传送 FTP
- 基于 **TCP**，使用**两条连接**：控制连接（端口 21，全程保持，传送命令与应答）+ 数据连接（端口 20 或被动模式随机端口，每传一个文件建一条，传完释放）。
- 控制连接始终在线是 FTP 与 HTTP 的重要区别。
- TFTP 简单文件传送：基于 UDP 69，无认证、块编号 + 停止等待，适合无盘工作站引导。

## 电子邮件
- 三个主要协议：
  - **SMTP**（发送，TCP 25）：推协议，把邮件从客户端发到服务器、服务器之间转发；命令-响应式，邮件正文用 7 位 ASCII（需 MIME 扩展支持中文与附件）。
  - **POP3**（接收，TCP 110）：拉协议，下载到本地后服务器上通常删除，支持"下载并保留"模式。
  - **IMAP**（接收，TCP 143）：邮件始终留在服务器，支持文件夹、部分读取、状态同步，适合多设备。
- 用户代理 UA 与邮件服务器；邮件报文格式由 RFC 5322 首部 + 空行 + 正文组成。
- 注意区分：SMTP 用于"发与转发"，POP3/IMAP 用于"用户取信"，两者不能互换。
- 现代 Web 邮件（如网页邮箱）中，用户浏览器到服务器之间用 HTTP，服务器之间仍用 SMTP。

## 万维网 WWW 与 HTTP
- 基本概念：URL 统一资源定位符（`<协议>://<主机>:<端口>/<路径>`）、超文本、超媒体。
- 请求报文结构：请求行（方法 + URL + 版本）+ 首部行 + 空行 + 实体主体。
- 响应报文结构：状态行（版本 + 状态码 + 短语）+ 首部行 + 空行 + 实体主体。
- 主要方法：GET（请求资源）、POST（提交数据）、HEAD（只要首部，常用于探测）、PUT/DELETE（RESTful）、OPTIONS。
- **GET 与 POST 的区别**：GET 参数在 URL 中、有长度限制、可被缓存与收藏、语义是"获取"（幂等）；POST 参数在实体主体、无长度限制、不缓存、语义是"提交"、非幂等。
- 常见状态码：
  - 1xx 信息；2xx 成功（200 OK、201 Created、204 无内容）；
  - 3xx 重定向（**301 永久重定向**、302 临时、304 Not Modified 命中缓存）；
  - 4xx 客户端错（400 语法错、401 未认证、403 禁止、**404 未找到**）；
  - 5xx 服务器错（500 内部错误、502 网关错、503 服务不可用）。
- 连接类型：
  - 非持续连接（HTTP/1.0）：每个对象建一条 TCP，取一个含 10 张图的页面需 11 次 TCP 握手，开销大；
  - **持续连接**（HTTP/1.1 默认）：一条 TCP 传多个对象，分非流水线（等前一个响应再发下一个）与流水线（连续发）。
- Cookie 与 Session：HTTP 本身无状态，Cookie 是服务器发给客户端的小文本（Set-Cookie / Cookie 首部），用于识别用户与保持会话；Session 数据存在服务器，Cookie 里只放 Session ID，更安全。
- **HTTPS** = HTTP + TLS/SSL（TCP 443）：先握手协商密钥（非对称加密交换对称密钥），再用对称加密传输；靠 CA 证书验证服务器身份，防窃听、防篡改、防冒充。
- HTTP/2 改进：二进制分帧、多路复用（一条连接并发多个流，解决队头阻塞）、首部压缩 HPACK、服务器推送。
- Web 缓存 / 代理服务器：位于客户端与源服务器之间，命中缓存直接返回，减少源站压力与访问延迟；用条件 GET（If-Modified-Since）与源站校验新鲜度，返回 304 表示未修改。

## 动态主机配置与网络管理
- DHCP（见网络层）：应用层视角下是 C/S 模式，基于 UDP 广播。
- SNMP 网络管理：管理者 + 代理 + 管理信息库 MIB，用 UDP 161/162，靠 Get/Set/Trap 操作。

## 重点结论
- FTP 的控制连接与数据连接分离是核心考点；HTTP 只有一条连接（Keep-Alive 复用）。
- DNS 用 UDP 是因为查询短、需快速、失败可重传；区域传送要可靠才用 TCP。
- HTTP 无状态 + Cookie 有状态是"协议设计与实际应用"的折中范例。
- 304 Not Modified 不是错误，是缓存命中的正常响应，用于减少传输量。
- HTTPS 握手中非对称加密只用于交换对称密钥，真正传数据用对称加密（性能考虑）。

## 常见考题
- 画出 DNS 递归 + 迭代混合查询过程，说明各级服务器的返回内容。
- 计算 HTTP/1.0 非持续连接取回一个含 N 个图片的页面所需的总时间（2RTT + 传输 每对象）。
- 说明 FTP 控制连接与数据连接的作用及生命周期差异。
- 解释 Cookie 与 Session 的区别与联系，以及各自的存放位置与安全风险。
- 描述 HTTPS 握手的主要步骤（证书校验、密钥交换、对称加密传输）。
