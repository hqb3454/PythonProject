# 进程与线程（课程讲义摘要）

## 进程的概念与状态
- 进程是**程序的一次执行过程**，是系统进行资源分配和调度的基本单位（引入线程后，调度单位变为线程）。
- 进程实体 = 程序段 + 数据段 + PCB（进程控制块）；PCB 是进程存在的唯一标志。
- PCB 内容：进程标识、处理机状态（寄存器现场）、进程调度信息（优先级、状态）、资源清单。
- 三种基本状态：就绪（等 CPU）→ 运行（占 CPU）→ 阻塞（等事件）；加上创建态与终止态共五态。
- 状态转换：就绪→运行（被调度）；运行→就绪（时间片到/被抢占）；运行→阻塞（主动请求资源）；阻塞→就绪（资源到位，**不会直接回运行**）。
- 挂起态：进程被换到外存，分就绪挂起与阻塞挂起，引入原因是内存不足或用户/系统要求。

## 进程控制与通信
- 原语：创建、撤销、阻塞、唤醒、切换，执行期间不可中断（关中断实现）。
- 进程通信（IPC）三种方式：
  - **共享存储**：共享内存区，最快，需同步互斥配合；
  - **消息传递**：直接通信（指明对方 ID）/ 间接通信（信箱），用 send/receive 原语；
  - **管道通信**：半双工的字节流，写满阻塞、读空阻塞，本质是一块固定的共享缓冲区（需互斥）。

## 线程
- 线程是**程序执行的最小单位**，是 CPU 调度的基本单位；进程仍是资源分配的基本单位。
- 线程自己几乎不拥有资源，只保留 TCB、栈、寄存器；同进程的线程共享地址空间、文件、全局变量。
- 实现方式：用户级线程（内核不可见，切换快，但一个线程阻塞导致整个进程阻塞）与内核级线程（内核调度，可并行，切换开销大）；现代系统多为一对一或多对多模型。
- 进程 vs 线程切换开销：线程切换不换页表、不刷新 TLB，开销明显更小。

## 处理机调度
- 三个层次：高级调度（作业调度，外存→内存）/ 中级调度（内存调度，挂起与对换）/ 低级调度（进程调度，最频繁）。
- 调度方式：非剥夺（简单，不适于分时）/ 剥夺（可及时响应，需遵循优先权、短进程优先、时间片原则）。
- 评价指标：CPU 利用率、系统吞吐量、周转时间、等待时间、响应时间。

### 经典调度算法
| 算法 | 规则 | 特点 |
|---|---|---|
| FCFS | 按到达先后 | 对长作业有利、短作业不利；不可剥夺 |
| SJF/SPF | 选估计运行时间最短 | 平均等待时间最优，但长作业可能"饥饿"，且需预估时间 |
| 高响应比优先 HRRN | 响应比 =(等待+要求服务)/要求服务 | 兼顾长短作业，短作业与等待久的作业都受益 |
| 时间片轮转 RR | 每个进程一个时间片 | 公平、适合分时；时间片太大退化成 FCFS，太小切换开销大 |
| 优先级调度 | 按优先级 | 分静态/动态；低优先级进程可能饥饿，可用"老化"缓解 |
| 多级反馈队列 | 多级队列 + 降级 + 时间片递增 | 综合最优，是通用系统的主流方案 |

## 同步与互斥
- 临界资源：一次只允许一个进程使用的资源；临界区：访问临界资源的代码段。
- 互斥四原则：空闲让进、忙则等待、有限等待、让权等待（**忙等不满足让权等待**）。
- 实现方法：
  - 软件：单标志法、双标志先检查/后检查、Peterson 算法（满足前三原则）。
  - 硬件：关中断（仅适用于单处理机内核态）、TestAndSet / Swap 指令（不满足让权等待）。
- **信号量**：P（wait，申请资源）/ V（signal，释放资源）原语；整型信号量不满足让权等待，记录型信号量含阻塞队列。
  - 互斥信号量初值 1；同步信号量初值为可用资源数。
- 管程：把共享数据与操作封装，任一时刻只允许一个进程在管程内，用条件变量 wait/signal 同步（Java synchronized 即此思想）。

### 经典同步问题
- 生产者-消费者：`empty = n`、`full = 0`、`mutex = 1`；**先同步后互斥，P(empty) 与 P(mutex) 顺序不可颠倒，否则死锁**。
- 读者-写者：读进程可并发，写进程需独占；引入 `count` 计数器与 `rw` 互斥锁，读写公平可加 `w` 信号量实现"写优先"。
- 哲学家进餐：五根筷子；死锁风险，解法有"最多允许 4 人同时拿""左右同时可用才拿""奇偶号拿筷顺序不同"。
- 吸烟者问题：单生产者多消费者的经典同步模型。

## 死锁
- 四个必要条件：**互斥、不可剥夺、请求并保持、循环等待**；四个条件同时成立才可能死锁。
- 三种处理策略：
  - 预防：破坏四个条件之一（如资源一次性分配破坏"请求并保持"、有序分配破坏"循环等待"）。
  - 避免：**银行家算法**，每次分配前检查是否存在安全序列；需已知每个进程的最大需求。
  - 检测与解除：资源分配图化简；解除用资源剥夺、撤销进程、进程回退。
- 注意：系统不安全状态 ≠ 死锁，只是存在死锁的可能性。

## 重点结论
- 阻塞态的进程只能被"唤醒"转为就绪态，绝不可能直接变运行态——这是选择题高频陷阱。
- 生产者-消费者中两个 P 操作顺序写反会死锁；V 操作顺序无所谓。
- 信号量初值为 1 时是互斥锁，初值为 n 时是资源计数，初值为 0 时常用于"前驱同步"。
- 死锁避免（银行家算法）需要进程提前声明最大需求，实际系统很少用，多数用预防 + 超时重试。

## 常见考题
- 给定进程到达时间与服务时间，用 FCFS / SJF / RR / HRRN 计算周转时间与平均等待时间。
- 用信号量描述生产者-消费者、读者-写者问题并说明信号量初值含义。
- 给定资源分配表，用银行家算法判断某次请求是否可以分配，并给出一个安全序列。
- 判断进程状态转换图中哪些转换是合法的（如"阻塞→运行""就绪→阻塞"均为非法）。
