# 计算机网络（课程讲义摘要）

## 分层模型
- OSI 七层：物理、数据链路、网络、传输、会话、表示、应用（教学模型）。
- TCP/IP 四层（实际使用）：网络接口、网络（IP）、传输（TCP/UDP）、应用（HTTP/DNS/FTP）。
- 每一层只与相邻层交互；下层为上层提供服务，上层对下层透明。

## TCP vs UDP
- TCP：面向连接、可靠传输（确认+重传）、有序、字节流、拥塞控制；开销大。
- UDP：无连接、不保证可靠/有序、数据报文、开销小、支持一对多广播。
- 选择依据：网页/文件传输用 TCP；实时音视频、DNS 查询用 UDP。

## TCP 三次握手（建立连接）
1. 客户端发 SYN（seq=x）；
2. 服务端回 SYN+ACK（seq=y, ack=x+1）；
3. 客户端回 ACK（ack=y+1），连接建立。
- 为什么三次而不是两次：防止历史失效的 SYN 到达服务端后建立错误连接；同时让双方都确认"我发你收、你发我收"四个能力。

## TCP 四次挥手（释放连接）
1. 主动方发 FIN；2. 对方回 ACK（此时对方可能还有数据要发）；3. 对方发 FIN；4. 主动方回 ACK 并进入 TIME_WAIT（等待 2MSL）。
- TIME_WAIT 的意义：保证最后的 ACK 能重传到达；让旧连接报文在网络中消亡。
- 为什么四次：TCP 全双工，两个方向要分别关闭；被动方"ACK"和"FIN"之间可能还有数据。

## HTTP 基础
- HTTP/1.1 默认长连接（keep-alive）；无状态，靠 Cookie/Session 维持状态。
- 常见状态码：200 成功、301 永久重定向、404 资源不存在、500 服务器内部错误。
- HTTPS = HTTP + TLS：非对称交换密钥 + 对称加密传输，默认端口 443。

## 重点结论
- TCP 可靠性靠：序列号（有序）、确认应答、超时重传、校验和、拥塞控制（慢启动、拥塞避免、快重传、快恢复）。
- DNS 用 UDP 53 端口（查询小而快）；大于 512 字节的响应改用 TCP。
- 滑动窗口控制流量：接收窗口（rwnd）防接收方过载，拥塞窗口（cwnd）防网络过载，发送窗口 = min(两者)。

## 常见考题
- 画出并解释三次握手/四次挥手各报文的 seq/ack 变化。
- 为什么握手三次、挥手四次？TIME_WAIT 为什么等 2MSL？
- 拥塞控制在慢启动阶段 cwnd 如何增长（每 RTT 翻倍，直到 ssthresh）？
- 从输入 URL 到页面显示，经过了哪些协议环节（DNS→TCP→TLS→HTTP→渲染）？
