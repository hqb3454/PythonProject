# 指令系统（课程讲义摘要）

## 指令的基本格式
- 指令 = 操作码 OP（做什么）+ 地址码 A（操作数在哪，结果放哪）。
- 按地址码数量分类：
  - 零地址：只有操作码，操作数在栈顶（堆栈计算机）；
  - 一地址：`OP A`，另一个操作数隐含在累加器 ACC；
  - 二地址：`OP A1, A2`，结果默认存回 A1；
  - 三地址：`OP A1, A2, A3`，结果写入 A3，最直观但指令字最长；
  - 四地址：还给出下一条指令地址（极少用，会破坏 PC 自动加一）。
- 指令字长：定长指令字（规整、取指快）与变长指令字（省空间，x86 典型）；还与机器字长、存储字长有关。

## 扩展操作码技术
- 在指令字长固定的前提下，让地址数多的指令用短操作码、地址数少的用长操作码。
- 关键规则：**短操作码不能是长操作码的前缀**（前缀编码原则），否则译码会有二义性。
- 考点：给定指令字长与地址字段位数，求各类指令各能有多少条（按 2 的幂递减分配）。

## 寻址方式（重点）
| 方式 | 有效地址 | 特点 |
|---|---|---|
| 立即寻址 | 操作数就在指令中 | 最快，不访存；只能作源操作数 |
| 直接寻址 | EA = A | 访存 1 次，地址范围受字长限制 |
| 间接寻址 | EA = (A) | 访存 2 次，可扩大寻址范围，便于共享 |
| 寄存器寻址 | EA = Ri | 不访存，最快，寄存器少故地址位短 |
| 寄存器间接 | EA = (Ri) | 访存 1 次，访问数组/指针常用 |
| 相对寻址 | EA = (PC) + A | 用于转移指令，支持**浮动程序** |
| 基址寻址 | EA = (BR) + A | 基址寄存器由 OS 设定，面向系统，用于多道程序定位 |
| 变址寻址 | EA = (IX) + A | 变址寄存器由用户改，面向用户，用于数组循环遍历 |
| 堆栈寻址 | 栈顶指针隐含 | 零地址指令，用于表达式求值、过程调用 |

- 基址与变址的区别是高频考点：基址寄存器内容由操作系统控制、程序不可改；变址寄存器内容由用户程序改变、形式地址 A 通常是数组首址。

## 指令类型
- 数据传送（MOV / LOAD / STORE / PUSH / POP）、算术逻辑（ADD / SUB / AND / OR / SHIFT）、
  移位、转移（无条件 / 条件 / 调用 CALL / 返回 RET / 陷阱）、输入输出、特权指令（只能在内核态执行）。
- 转移指令的寻址常用相对寻址，偏移量用补码表示，可正可负。

## CISC 与 RISC
| 对比项 | CISC（x86） | RISC（ARM / MIPS / RISC-V） |
|---|---|---|
| 指令数 | 数百条，功能复杂 | 几十条，功能单一 |
| 指令字长 | 变长 | 定长 |
| 访存指令 | 允许运算指令访存 | 只有 LOAD / STORE 访存 |
| 通用寄存器 | 较少 | 较多（几十个） |
| 实现方式 | 微程序控制为主 | 硬布线为主，便于流水线 |
| 代码密度 | 高 | 低（现代有压缩指令扩展） |

## 重点结论
- 寻址方式决定了「指令能访问到的数据范围」和「有效地址形成的速度」，是本章与 CPU 数据通路的衔接点。
- 相对寻址让程序可以整体搬到内存任意位置而不用改地址，是程序浮动的基础。
- 条件转移的实现依赖状态寄存器中的标志位（ZF / SF / CF / OF），由前一条运算指令置位。
- 指令系统是软硬件的接口（ABI 层面），向后兼容是 CISC 背负的历史包袱，也是 x86 长盛的原因。

## 常见考题
- 给定指令字长 16 位、每个地址 4 位，求三地址、二地址、一地址指令各最多多少条（扩展操作码）。
- 判断某条指令采用哪种寻址方式，并写出访存次数与有效地址表达式。
- 比较基址寻址与变址寻址的适用场景。
- 说明转移指令为什么常用相对寻址而非直接寻址。
