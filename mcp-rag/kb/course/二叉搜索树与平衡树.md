# 数据结构 · 二叉搜索树与平衡树（课程讲义摘要）

## 二叉搜索树 BST
- 性质：对任意结点，**左子树所有结点值 < 根结点值 < 右子树所有结点值**；中序遍历得到**递增有序序列**（这是 BST 最重要的特征）。
- 查找：从根开始，比当前结点小则走左、大则走右；查找长度取决于树的高度。
- 插入：先查找，失败位置的空指针处插入新结点（总是作为叶子插入）。
- 删除（三种情况）：
  1. 叶子结点：直接删除；
  2. 只有一棵子树：用子树顶替该结点位置；
  3. 有两棵子树：用**中序前驱**（左子树最右结点）或**中序后继**（右子树最左结点）的值替换，再删除那个前驱/后继结点（它至多一棵子树，退化为情况 1 或 2）。
- 查找效率分析：
  - 平均查找长度 ASL 与树的形状有关；最好情况（接近完全二叉树）O(log n)，最坏情况（退化成单支链表）O(n)。
  - 等概率下，n 个结点的随机 BST 平均高度约为 O(log n)。
  - 由给定插入序列构造的 BST **与插入顺序有关**，同一组关键字不同顺序可能得到不同形态的树。

## 平衡二叉搜索树 AVL
- 平衡因子 BF = 左子树高度 - 右子树高度；AVL 要求每个结点 |BF| ≤ 1，即任意结点左右子树高度差不超过 1。
- 结点数 n 与最小高度 h 的关系：`N(h) = N(h-1) + N(h-2) + 1`，N(0)=1、N(1)=2；据此可求给定结点数的最小树高或给定高度的最少结点数。
- 插入后失衡的四种类型与旋转：
  - **LL（右单旋）**：失衡结点的左孩子的左子树插入 → 向右旋转一次；
  - **RR（左单旋）**：右孩子的右子树插入 → 向左旋转一次；
  - **LR（先左后右双旋）**：左孩子的右子树插入 → 先对左孩子左旋，再对失衡结点右旋；
  - **RL（先右后左双旋）**：右孩子的左子树插入 → 先对右孩子右旋，再对失衡结点左旋。
- 关键细节：插入时只需调整**最小不平衡子树**（从插入点向上找第一个失衡的祖先），旋转后其它子树高度不变，无需继续向上调整。
- 删除后失衡可能不止一处，需要**一直向上调整到根**。
- 含有 n 个结点的 AVL 树高度为 O(log n)；查找、插入、删除最坏均为 O(log n)；删除需 O(log n) 次旋转。
- 代价：为维持平衡需频繁旋转，插入删除频繁时开销大；适合**查找多、增删少**的场景。

## 红黑树
- 五条性质：① 结点非红即黑；② 根是黑；③ 所有叶子（NIL）是黑；④ 红结点的子结点必须是黑（不能连续红）；⑤ 从任一结点到其所有后代 NIL 的**黑色结点数相同**（黑高相同）。
- 保证：**最长路径不超过最短路径的 2 倍**，树高 O(log n)，是一种"弱平衡"。
- 与 AVL 对比：AVL 更严格平衡（查找更快），红黑树旋转次数更少（插入删除更快）。
- 应用：C++ STL 的 map/set、Java TreeMap、Linux 内核的进程调度 CFS 与虚拟内存管理、epoll 的事件表。

## B 树与 B+ 树
- 引入原因：磁盘 I/O 远慢于内存，需要降低树的高度以减少磁盘访问次数（**多路平衡查找树**）。
- **m 阶 B 树**：
  - 每个结点最多 m 棵子树（m-1 个关键字）；非叶根结点至少 2 棵子树，其他非叶结点至少 ⌈m/2⌉ 棵子树；
  - 所有叶子在同一层，不带信息（失败结点）；
  - 结点内的关键字有序，Ki 左右子树分别小于/大于 Ki。
- **m 阶 B+ 树**（与 B 树的关键区别）：
  - 结点的子树个数与关键字个数**相等**（B 树为关键字数 + 1）；
  - **所有关键字都在叶子结点中出现**，非叶结点只作索引（因此查询必须走到叶子，路径长度稳定）；
  - 叶子结点用指针串成链表，非常适合**范围查询与全表扫描**；
  - 是数据库索引（如 MySQL InnoDB）与文件系统的标准结构。
- 插入导致关键字数超限时**从中间分裂**，并把中间关键字上移；删除导致不足时借位或与兄弟**合并**。
- 高度：n 个关键字的 m 阶 B 树高度约为 `log⌈m/2⌉((n+1)/2) + 1`，m 越大树越矮、磁盘 I/O 越少。

## 哈夫曼树与哈夫曼编码
- 带权路径长度 WPL = Σ(权值 × 路径长度)；哈夫曼树是**WPL 最小的二叉树**，也称最优二叉树。
- 构造算法（贪心）：每次选权值最小的两棵树合并，新树根权值为两者之和，重复直到只剩一棵；共合并 n-1 次。
- 性质：哈夫曼树**不一定唯一**（权值相同时合并顺序不同），但最小 WPL 唯一；没有度为 1 的结点；n 个叶子的哈夫曼树共 2n-1 个结点。
- 哈夫曼编码：左分支记 0、右分支记 1，叶子的编码即该字符的编码；是**前缀编码**（任一编码不是其他编码的前缀），可无歧义解码。
- 与定长编码相比，哈夫曼编码能显著压缩数据；属于无损压缩。

## 重点结论
- BST 的中序遍历有序，这是判断一棵树是否为 BST 的根本依据（只看单结点大小关系不够）。
- BST 退化的根源是插入序列有序（如递增插入），解决办法就是引入自平衡（AVL / 红黑树 / 跳表）。
- AVL 的四种旋转只记"最小不平衡子树 + 失衡类型"即可，插入最多旋转一次，删除可能旋转多次。
- B+ 树相比 B 树的两大优势：查询性能稳定（都到叶子）、支持高效范围扫描（叶子链表）。
- 哈夫曼编码是前缀码，解码时不会出现二义性；编码长度与字符出现频率相关，频率高的短。

## 常见考题
- 由给定插入序列构造 BST，画出最终形态并计算等概率下的成功/失败 ASL。
- 删除 BST 中某个有两个孩子的结点，写出用中序后继替换的完整过程。
- 给定插入序列导致 AVL 失衡，判断失衡类型（LL/RR/LR/RL）并画出旋转后的树。
- 求 n 个结点的 AVL 树的最小/最大高度；或已知高度求最少结点数。
- 给定字符集与频率，构造哈夫曼树，写出各字符编码并计算 WPL 与压缩率。
- 比较 B 树与 B+ 树在单点查询、范围查询上的差异。
