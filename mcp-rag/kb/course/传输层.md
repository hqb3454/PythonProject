# 计算机网络 · 传输层（课程讲义摘要）

## 传输层的作用
- 传输层提供**应用进程之间的逻辑通信**（网络层提供的是主机之间的逻辑通信）。
- 两项核心功能：**复用与分用**（多个进程共用传输层，靠端口号区分）+ **差错检测**（网络层首部检验和不检验数据）。
- 端口：16 位，0~1023 为熟知端口（HTTP 80 / HTTPS 443 / FTP 21 / SSH 22 / DNS 53 / SMTP 25），1024~49151 为登记端口，其余为客户端短暂端口。
- 套接字 socket = (IP 地址: 端口号)，唯一标识一台主机上的一个应用进程。

## UDP 用户数据报协议
- 特点：**无连接、尽最大努力交付、面向报文、无拥塞控制、首部开销小（8 字节）**。
- 首部：源端口(16) | 目的端口(16) | 长度(16) | 检验和(16)。
- UDP 检验和计算时需要加上 12 字节**伪首部**（源 IP、目的 IP、0、协议号 17、UDP 长度），用于验证数据是否送到了正确的主机与端口。
- 面向报文：应用层交给 UDP 多长的报文，UDP 原样发送，不拆分也不合并；报文太长会导致 IP 层分片。
- 适用场景：DNS、DHCP、音视频实时传输、QUIC 的底层（容忍少量丢失，追求低延迟）。

## TCP 传输控制协议
- 特点：**面向连接、可靠交付、全双工、面向字节流、点对点**。
- TCP 报文段首部（20 字节固定）：源端口 | 目的端口 | 序号 seq | 确认号 ack | 数据偏移 | 保留 | **6 个控制位**（URG/ACK/PSH/RST/SYN/FIN）| 窗口 | 检验和 | 紧急指针 + 选项（MSS、窗口扩大、时间戳、SACK）。
  - 序号：本报文段所发送数据的**第一个字节**在整个字节流中的编号。
  - 确认号：**期望收到的下一个字节的序号**（表示该序号之前的所有字节都已正确收到）。
  - 窗口字段：接收方当前允许发送方发送的数据量，用于流量控制（接收窗口 rwnd）。

## TCP 连接管理
- 三次握手：
  1. 客户端发 `SYN=1, seq=x`（不携带数据，消耗 1 个序号）；
  2. 服务器回 `SYN=1, ACK=1, seq=y, ack=x+1`；
  3. 客户端回 `ACK=1, seq=x+1, ack=y+1`（可携带数据）。
- **为什么要三次而不是两次**：防止已失效的连接请求报文突然到达服务器，导致服务器错误地建立连接并白白等待（两次握手下服务器无法确认客户端是否真的想建立连接）。
- 四次挥手：
  1. 主动方 `FIN=1, seq=u`；
  2. 被动方 `ACK=1, ack=u+1`（此时处于**半关闭**状态，被动方仍可继续发数据）；
  3. 被动方数据发完后 `FIN=1, seq=v`；
  4. 主动方 `ACK=1, ack=v+1`，进入 **TIME-WAIT**。
- **TIME-WAIT 为什么要等 2MSL**：① 保证最后一个 ACK 能到达对方（丢失时对方会重发 FIN，本方能重发 ACK）；② 让本次连接的所有残留报文在网络中消散，避免干扰后续使用相同 socket 的新连接。
- SYN 洪泛攻击：攻击者发大量 SYN 不回 ACK，耗尽服务器半连接队列；防御手段是 SYN cookie。

## TCP 可靠传输
- 以字节为单位的滑动窗口：发送窗口内的字节可连续发送，不必等逐个确认。
- 超时重传时间 RTO 的计算：
  - 加权平均往返时间 `RTTS = (1-α)·RTTS + α·RTT样本`（α 通常取 1/8）；
  - 偏差 `RTTD = (1-β)·RTTD + β·|RTTS - RTT样本|`（β 通常取 1/4）；
  - `RTO = RTTS + 4·RTTD`；Karn 算法规定重传的报文段不用于更新 RTT 估计。
- **选择确认 SACK**：接收方告知已收到的不连续字节块，发送方只重传缺失部分，避免不必要的重传。
- 快速重传：收到 3 个重复 ACK 就立即重传丢失的报文段，不等超时。

## TCP 流量控制
- 目的：让发送方发送速率不超过接收方的处理能力，是**端到端**的问题。
- 靠接收窗口 rwnd 实现：接收方在确认中通告自己的接收窗口；发送窗口 = min(拥塞窗口 cwnd, 接收窗口 rwnd)。
- 零窗口僵局：接收方通告窗口为 0 后，恢复通知丢失会导致双方互等；解法是接收方允许时用**持续计时器**发送零窗口探测报文。

## TCP 拥塞控制
- 目的：防止过多数据注入网络，是**全局性**的问题（涉及所有主机与路由器）。
- 四个算法（ Tahoe 版含慢开始 + 拥塞避免 + 快重传 + 快恢复 Reno 版）：
  1. **慢开始**：cwnd 从 1 个 MSS 起，每收到一个 ACK 就 +1，实际效果是**每轮 RTT 翻倍**（指数增长）；到达 ssthresh 后转拥塞避免。
  2. **拥塞避免**：每轮 RTT 只 +1 个 MSS（线性增长，也称加法增大 AI）。
  3. **快重传**：3 个重复 ACK 立即重传丢失报文段。
  4. **快恢复**：发生快重传时把 ssthresh 和 cwnd 都设为当前 cwnd 的一半，然后执行拥塞避免（Reno 不再回到慢开始，这是与 Tahoe 的关键区别）。
- 判断拥塞的依据：
  - 超时：认为拥塞严重 → ssthresh = cwnd/2，cwnd 重置为 1，重新慢开始（**乘法减小 MD**）。
  - 3 个重复 ACK：认为只是个别丢包 → 快重传 + 快恢复。
- AIMD：加法增大、乘法减小，整体呈锯齿状（拥塞窗口的"锯齿"曲线是课本标志性图）。

## 重点结论
- 三次握手最少不能少于三次；四次挥手之所以是四次，是因为被动关闭方的 ACK 与 FIN 分开发（中间可能还有数据要发）。
- 确认号 = 已收到的最后一个字节序号 + 1；SYN 和 FIN 即使不携带数据也要各消耗 1 个序号。
- 流量控制是点对点的接收能力问题（rwnd），拥塞控制是网络全局问题（cwnd），两者共同决定发送窗口。
- 慢开始不是"慢"，它是指数增长；名为慢是因为起点低（1 个 MSS）。
- TCP 面向字节流，UDP 面向报文——这是两者最本质的区别之一，直接影响应用层是否需要自己处理消息边界（粘包/拆包）。

## 常见考题
- 画出三次握手与四次挥手的报文序列，写出各阶段的 SYN/ACK/FIN 标志与 seq/ack 取值。
- 说明 TIME-WAIT 存在的两个理由与 2MSL 的含义。
- 给定初始 ssthresh 与一系列 RTT 内的丢包事件，画出拥塞窗口随时间的变化曲线。
- 计算 RTO（给定 RTT 样本序列与 α、β）。
- 说明超时重传与快重传在判断拥塞程度与后续处理上的区别。
