# 数据库原理（课程讲义摘要）

## 关系模型与范式
- 关系 = 二维表；候选键能唯一标识元组，主键从候选键中选出，外键引用其他表的主键。
- 范式（逐级消除冗余）：
  - 1NF：字段原子，不可再分；
  - 2NF：消除非主属性对主键的**部分**依赖（只看联合主键）；
  - 3NF：消除非主属性对主键的**传递**依赖；
  - BCNF：所有函数依赖的决定因素都必须是候选键。
- 实际开发常在 3NF 与查询性能之间权衡（适度冗余减少 JOIN）。

## 事务与 ACID
- 原子性（A）：要么全做要么全不做——靠 undo log 回滚。
- 一致性（C）：约束与业务规则不被破坏——是最终目标。
- 隔离性（I）：并发事务互不干扰——靠锁 + MVCC。
- 持久性（D）：提交即持久——靠 redo log/WAL。
- 并发问题与隔离级别：读未提交（脏读）→ 读已提交（不可重复读）→ 可重复读（幻读，MySQL InnoDB 默认）→ 串行化（全解决但最慢）。

## 索引与 B+ 树
- 为什么用 B+ 树而不是二叉树/哈希：矮胖结构（3-4 层可存千万行）→ 磁盘 I/O 次数少；哈希不支持范围查询；有序支持排序与最左前缀。
- 叶子节点存全部数据并用链表串联 → 范围扫描高效；非叶子节点只存键 → 单页能放更多索引项。
- 聚簇索引（主键，叶子存整行）vs 二级索引（叶子存主键值，查非索引列需"回表"）。
- 最左前缀原则：联合索引 (a,b,c) 只对 a、(a,b)、(a,b,c) 有效；遇到范围查询后面的列不再使用索引。

## SQL 要点
- JOIN：INNER（交集）/ LEFT（左表全保留）/ RIGHT / FULL；小表驱动大表。
- 分组聚合：WHERE 在分组前过滤行，HAVING 在分组后过滤组。
- 查询优化：避免 SELECT *、函数作用在索引列上会使索引失效、注意隐式类型转换。

## 重点结论
- 事务隔离级别越高，并发性能越差；MySQL InnoDB 默认可重复读，并通过 MVCC + 间隙锁在很大程度上避免幻读。
- EXPLAIN 是调优第一工具：关注 type（至少 range）、rows、extra（避免 filesort/temporary）。
- 索引不是越多越好：每个索引拖慢写入、占用空间，高频查询字段才值得建。

## 常见考题
- 给一张表判断最高满足第几范式，如何拆到 3NF。
- 四个隔离级别分别解决/不解决哪些并发问题。
- 解释"回表"与"覆盖索引"（查询列都在索引里则免回表）。
- 联合索引 (a,b,c)，以下查询哪些能走索引：WHERE a=? / WHERE b=? / WHERE a=? AND b>? AND c=?
