# 操作系统（课程讲义摘要）

## 进程与线程
- 进程是资源分配的基本单位（拥有独立的虚拟地址空间、文件描述符表）；线程是 CPU 调度的基本单位（共享所在进程的地址空间）。
- 进程切换需要切换页表和内核栈，开销大；线程切换只切换寄存器和栈，开销小。
- 进程间通信（IPC）：管道、消息队列、共享内存（最快，需配信号量同步）、信号量、socket。
- 线程同步：互斥锁、条件变量、读写锁、信号量。

## CPU 调度算法
- FCFS（先来先服务）：简单、对短作业不公平（护航效应）。
- SJF（短作业优先）：平均等待时间最优，但可能是非抢占的，长作业可能饿死。
- 时间片轮转（RR）：公平、响应快；时间片太短则上下文切换开销大，太长则退化为 FCFS。
- 优先级调度：可能饿死低优先级任务，需"老化"（等待越久优先级越高）缓解。
- 多级反馈队列：综合以上优点，是通用系统的主流选择。

## 内存管理
- 连续分配会产生**外部碎片**；分页（paging）消除外部碎片，但页内存在**内部碎片**。
- 虚拟地址 = 页号 + 页内偏移；页表完成虚拟页 → 物理页框的映射。
- TLB（快表）：缓存页表项，将地址翻译从多次访存降为接近一次。
- 页面置换算法：FIFO（可能 Belady 异常）、LRU（最久未使用，效果好但开销大）、Clock（近似 LRU，开销小）。

## 死锁
- 四个必要条件：互斥、持有并等待、不可抢占、循环等待——破坏任一即可预防。
- 银行家算法：分配前检查系统是否仍处于安全状态，属于**死锁避免**。
- 资源有序分配法：给资源编号并要求按序申请，破坏"循环等待"。

## 重点结论
- 线程不拥有独立地址空间；同一进程的线程切换不切换页表。
- Belady 异常只出现在 FIFO（页框增多、缺页反而增多），LRU/OPT 不会出现。
- 死锁处理四策略：预防（最保守）→ 避免（银行家）→ 检测与恢复 → 鸵鸟策略（Linux 实际做法）。

## 常见考题
- 比较进程与线程的区别；说明为什么线程切换比进程切换快。
- 给定页面访问序列和页框数，计算 FIFO/LRU 的缺页次数。
- 证明死锁四条件中破坏哪一个代价最小（通常答：循环等待，资源有序分配）。
- 银行家算法判断某次分配是否安全，写出安全序列。
